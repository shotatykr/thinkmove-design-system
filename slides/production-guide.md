# Slide Production Guide

## 1. 資料制作の目的

ThinkMoveの資料は、情報を装飾するためではなく、読み手の判断と実行を前へ進めるために作る。

制作前に、内部メモとして次を1文で定義する。

> この資料を読み終えたとき、［対象者］が［判断・理解・行動］できる。なぜなら［中心となる結論］が明らかになるからである。

さらに次の5項目を固定する。

- Audience：誰が読むか
- Job：この資料が果たす仕事
- Decision：相手に何を決めてほしいか
- Takeaway：中心となる結論
- Evidence：結論に必要な根拠

未確定情報を勝手に埋めない。意思決定に影響する不足は、確認事項またはプレースホルダーとして残す。

## 2. ストーリー

### 提案・分析資料

1. 今回の問い・判断事項
2. 現状と確認できた事実
3. 重要な論点・原因の解釈
4. 選択肢または対応方針
5. 推奨案と理由
6. 実行方法・役割・順序
7. 次のアクション

### 登壇・研修資料

1. 現場で起きている違和感
2. よくある理解と、その限界
3. 実務から得られた見方
4. 具体例、画面、デモ
5. 自分の仕事への適用方法
6. 今日から試せる一歩

アジェンダは物語ではない。各スライドが前の疑問を解き、次の疑問を生むように並べる。

## 3. 1枚1メッセージ

- 1枚の主要な主張は1つ
- タイトルだけを順に読んでも、資料全体の論理が追える
- タイトルはテーマ名ではなく、結論または意味を書く
- 前のスライドと同じことを言い換えるだけのページを作らない
- 内容が収まらない場合、文字を縮めずスライドを分ける

悪いタイトル：

- 現状分析
- AI活用の課題
- 今後の方針
- SEOについて

良いタイトル：

- 流入減少の主因は、順位低下ではなく検索需要の縮小です
- AIを配るだけでは、確認作業が新しいボトルネックになります
- まず回復可能性の高い5本から検証します

タイトルは、豊藏がその場で自然に口にできる文章にする。広告コピーのような抽象語や、機械的に整いすぎた標語を量産しない。

## 4. 事実・解釈・提案

3種類を混同しない。

| 種類 | 内容 | 例 |
|---|---|---|
| 事実 | データ、観測、発言、確認済み情報 | 自然検索クリック数は前月比18%減少した |
| 解釈 | 事実から読み取れる意味 | 非指名検索の減少影響が大きい |
| 提案 | ThinkMoveとして推奨する行動 | 回復余地のある非指名記事から再評価する |

数字には、比較対象、期間、母数、意味を添える。グラフやスクリーンショットを置くだけで終わらせず「だから判断がどう変わるか」を示す。

## 5. 情報密度

ThinkMoveの資料は、余白だけのポスターではない。「実務密度のある冷静な共感」を基準にする。

- 本文は原則3〜5項目
- 箇条書き1項目は原則2行以内
- 本文17〜20pt、スライドタイトル30〜36ptを目安
- 注釈・出典を除き、本文を17pt未満に縮めない
- 1枚に小さなカードを大量に敷き詰めない
- KPI、手順、判断材料、保留、次の一手のいずれかを置く
- 詳細条件、調査過程、例外は付録またはノートへ移す

## 6. 基本レイアウト

既存の詳細な型は[`../examples/slides/`](../examples/slides/)を正とする。以下は不足時に使う構造。

| Pattern | 用途 | 構造 |
|---|---|---|
| Decision Frame | 冒頭の判断固定 | 今回の問い＋判断観点3つ以内 |
| Claim + Evidence | 分析・提案理由 | 左に意味、右にグラフ・画面・表 |
| Fact / Interpretation / Action | 定例・診断 | 事実→解釈→次の行動 |
| Options + Recommendation | 案比較 | 2〜4案、比較軸3〜5個、推奨理由 |
| Prioritization Map | 優先順位 | 2軸、優先領域、対象、次の検証 |
| Process | 手順 | 3〜5段階、動詞見出し、成果物 |
| Roadmap | 実行計画 | 時間、担当、判断日、依存関係 |
| KPI / Big Number | 成果・変化 | 数字、比較期間、母数、意味 |
| Action Register | 会議の締め | Action / Owner / Due / Done when |
| Closing Resolution | 最終ページ | 冒頭の問いへの答え＋最初の一歩 |

同じ構図を意図なく3枚以上続けない。ただし連続比較では統一を優先する。

## 7. 視覚ルール

数値は[`../theme/design.json`](../theme/design.json)を正とする。

- 16:9
- 白70% / Navy 15% / Gray 10% / Teal 4% / Orange 1%
- Tealは前進・次のアクション・CTA
- Orangeは1点の注意・変化・限定強調のみ
- カードはshadow-as-border。太線で囲まない
- 左右余白、タイトル位置、本文開始位置を資料内で揃える
- ロゴは原則右上。公式アセットを後処理で合成する
- グラフは注目系列だけを色で強調し、その他はgrayへ落とす
- 色だけで意味を伝えず、ラベルや位置でも区別する

## 8. 資料別の調整

### 提案資料

- 読み手が選ぶ判断を最初に定義する
- 課題を網羅せず、推奨案に必要な論点へ絞る
- 必要に応じて採用しなかった選択肢と理由も示す
- 最終ページに、決めてほしいことと開始条件を置く

### 定例・分析報告

- 前回から何が変わったかを先に示す
- 変化→解釈→次の検証をつなぐ
- 未確認情報と推測を分ける
- 実施済み、進行中、相手待ち、判断待ちを混同しない

### 要件定義・実行計画

- 目的、対象範囲、非対象、完了条件を明記する
- タスク一覧より、依存関係と判断ポイントを優先する
- 担当、期限、入力、成果物、確認者を定義する

### 登壇・研修

- 提案資料より1枚の情報量を減らす
- 発表者が話す内容を全文掲載しない
- 具体例、画面、デモ、短い問いを入れる
- 今日試せる一歩で閉じる

## 9. 禁止事項

- テーマ名だけのタイトルを連続させる
- 小さい文字で情報を詰め込む
- 根拠のない数字、架空の引用、架空の成果を作る
- データと推測を同じトーンで断定する
- きれいだが判断材料のないポスターにする
- HTML/CSSの画面キャプチャ風デザインにする
- OrangeをCTAや広い背景へ使う
- 最後を「まとめ」「Thank you」だけで終える

## 10. 完成の定義

ファイルを生成しただけでは完成ではない。

- タイトルだけで論理が追える
- 事実・解釈・提案が分かれている
- 読み手が判断すべきことが明確
- 次のアクションが具体的
- 文字切れ、重なり、不自然な改行がない
- 数字、グラフ、本文、出典が一致している
- 全ページをレンダリングして目視確認している
